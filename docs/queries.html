Eight queries that need both halves

Five queries where the vector index and the OWL 2 EL reasoner each do work the other cannot, and three that are pure classification. Every result below was returned by a live t50 instance — the timings and cosine scores are what it actually answered.

Before you paste

setup

The API takes OxQL over POST /query. The Content-Type header is not optional — without it the server answers “Expected request with Content-Type: application/json” and nothing runs.

shell 
export OXIDDB_URL=http://127.0.0.1:7978
export OXIDDB_API_KEY=your-token-here

curl -s -X POST "$OXIDDB_URL/query" \
  -H "Authorization: Bearer $OXIDDB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"FIND ?x WHERE ?x IS-A <http://dbpedia.org/ontology/BodyOfWater> LIMIT 8"}'

Similarity takes the words you would say out loud. The string after TO is embedded by the instance with the model the corpus was built on — text-embedding-3-small at 1,536 dimensions — so every query below pastes and runs unchanged, in the console at /app/query or over curl. Nothing to substitute, no vector to carry.

A literal vector still works, and is what you want when the probe should be an entity’s stored vector rather than a fresh embedding of its name — 1,536 plain decimals, no exponent, because OxQL’s number literals do not accept one. The instance will hand you one from any individual it holds.

shell · exact stored vector 
curl -s -H "Authorization: Bearer $OXIDDB_API_KEY" \
  "$OXIDDB_URL/individuals/http%3A%2F%2Fdbpedia.org%2Fresource%2FAlbert_Einstein" \
  | python3 -c 'import json,sys; v=json.load(sys.stdin)["vectors"]["dbpedia"]; print("["+",".join(f"{x:.6f}" for x in v)+"]")'

03 vector + ontology + literal

Add a constraint that bites

Similarity, inferred class, and a numeric data property in one pass. Note the second constraint drops Amsterdam itself — its population is under a million — and the answer climbs to the administrative units that clear the bar.

probe · "Amsterdam" 
FIND ?x WHERE ?x IS-A <http://dbpedia.org/ontology/PopulatedPlace>
  AND ?x.http://dbpedia.org/ontology/populationTotal > 1000000
  AND NEAR ?x.dbpedia TO "Amsterdam"
  LIMIT 8

Three asserted classes — AdministrativeRegion, City, Country — answering one PopulatedPlace question, ranked by embedding, filtered on a typed literal. That combination is the whole pitch.

One assertion in, five classes out

When someone asks where the answers come from, read a single individual back. IRIs in a URL path must be percent-encoded.

shell 
curl -s -H "Authorization: Bearer $OXIDDB_API_KEY" \
  "$OXIDDB_URL/individuals/http%3A%2F%2Fdbpedia.org%2Fresource%2FAlbert_Einstein" \
  | python3 -m json.tool
asserted → inferred
classesScientist inferred_classesAnimal · Eukaryote · Person · Scientist · Species

loader/oxd_oracle.py checks that whole derivation offline against oxd hierarchy and oxd extents, so what the reasoner claims is differentially verified rather than taken on trust.

Five ways to write it wrong

OxQL 0.9.9
<dbo:PopulatedPlace> <http://dbpedia.org/ontology/PopulatedPlace>

No prefix registry. A prefixed name is read as a class IRI literally spelled that way, and you get unknown class.

?x.<…/populationTotal> > 1000000 ?x.http://dbpedia.org/ontology/populationTotal > 1000000

Angle brackets are accepted only after IS-A. On a property they are a parse error — and omitting them there is a parse error too. Two spellings in one query.

TO Albert Einstein TO "Albert Einstein"

The probe after TO is a string literal or a vector literal, nothing else. Unquoted text — or a shell placeholder that never got substituted — stops at expected string_lit or vec_literal.

TO [1.4e-2, …] TO [0.014000, …]

OxQL number literals take no exponent. Format every component as a plain decimal.

?x.…/almaMater = <…/Harvard_University> — not supported —

Object-property filters do not work in queries. The edges are stored and come back on GET /individuals, but the bracketed form is a parse error and the quoted form matches nothing. Don’t promise “physicists who studied at Harvard” as a single query.
